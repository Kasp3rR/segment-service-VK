- База: настоящий контейнер PostgreSQL **16.15**, Alpine Linux, ARM64.

- Каждый интеграционный тест использовал собственную временную схему PostgreSQL.
- Существующие контейнеры других проектов не останавливались и не изменялись.


Успешно: gofmt, go vet, сборка `bin/api` и `bin/migrate`.

Полный финальный прогон после перехода на Gin и исправлений:

Все тесты прошли, ошибок детектора гонок нет. Число проверок рассчитано по событиям
`pass` в JSON-выводе Go. «Сценарий» — конечный тест или под-тест без вложенных под-тестов;

## Что проверено

- CRUD сегментов, уникальность и неизменяемость кода, пустое описание, Unicode-имена.
- Создание пользователей, дубликаты, положительный BIGINT и переполнение JSON-числа.
- Повторные добавление и удаление участия, отсутствие пользователя/сегмента.
- Сортировка, пагинация, изоляция назначений разных пользователей, пустые массивы.
- Каскадное удаление сегмента, ограничения и составной индекс PostgreSQL.
- 32 конкурентных назначения одной пары: остаётся одна запись.
- Одновременные PATCH разных полей: оба изменения сохраняются.
- Гонка удаления сегмента и назначения: нет осиротевших назначений.
- Четыре одновременных запуска миграций, повторное применение, откат и контроль checksum.
- Строгий JSON, неизвестные поля, null в PATCH, неверный Content-Type и лимит 64 KiB,
  включая слишком длинный хвост после JSON-объекта.
- Ошибки, отмена запроса к БД, readiness, обработка паники Gin, JSON-ошибки 404/405.

## Запуск приложения

```sh
docker compose up -d --build --wait
curl -fsS http://localhost:18080/readyz
curl -fsS http://localhost:18080/segments
curl -fsS http://localhost:18080/users/42/segments
docker compose exec -T api /app/migrate -direction=up
```

Результат: оба контейнера `healthy`; ответы — `{"status":"ready"}`, `[]`, `[]`.
Повторное применение миграций завершилось успешно. Первая холодная сборка задержалась
при загрузке Go-модулей; повторная сборка с диагностикой и кэшем BuildKit прошла,
последующий запуск использовал успешно собранный образ.

Дополнительно через настоящий HTTP проверен локально собранный `bin/api` на порту 18081:
создание пользователя и MAIL_GPT, чтение и PATCH сегмента, повторные PUT/DELETE участия,
получение сегментов пользователя, запрет изменения кода, удаление сегмента и ответ 404.
После SIGTERM процесс завершился с кодом 0. Временный HTTP-процесс остановлен.

После проверки в локальной базе остался пользователь `42` без назначений;
тестовый сегмент MAIL_GPT удалён. Интеграционные схемы удалены тестовыми cleanup-функциями.

## Границы этапа

Авторизация и внешний деплой в текущий этап не входят; Compose предназначен для локальной разработки.

После этой правки повторно успешно выполнены `make check build` и `go test -race -tags=integration -count=1 ./...` с реальной PostgreSQL. Контрольная сумма локальной миграции обновлена с проверкой предыдущего значения; пользовательские данные сохранены.
